## Answers to Interview Questions

**I. Fundamentals of OOP Concepts:**

1.  **What is Object-Oriented Programming (OOP)? What are its main principles?**
    *   **Answer:** OOP is a programming paradigm based on the concept of "objects," which can contain data (attributes/fields) and code (methods/procedures). It aims to organize and structure code around objects rather than actions, improving modularity, reusability, and maintainability.
    *   **Main Principles (often called pillars of OOP):**
        *   **Encapsulation:** Bundling data (attributes) and methods that operate on that data into a single unit (object/class) and hiding internal implementation details from the outside world.
        *   **Abstraction:**  Simplifying complex reality by modeling classes based on essential characteristics and hiding unnecessary details. Showing only relevant information to the user.
        *   **Inheritance:**  Mechanism where a new class (subclass/derived class) inherits properties and behaviors from an existing class (superclass/base class), promoting code reusability and establishing "is-a" relationships.
        *   **Polymorphism:**  Ability of an object to take on many forms.  Allows objects of different classes to be treated as objects of a common type (e.g., through interfaces or inheritance) and respond differently to the same method call.

2.  **Explain the concept of "Class" and "Object" in OOP. How are they related?**
    *   **Answer:**
        *   **Class:** A blueprint or template for creating objects. It defines the type of object, specifying the attributes (data) an object of that class will have and the methods (behavior) it can perform.  Think of it as a design or a category.
        *   **Object:** An instance of a class. It's a concrete entity created based on the class blueprint. Each object has its own state (values for attributes) and can perform the methods defined in its class.  Think of it as a specific instance belonging to a category.
    *   **Relationship:** Classes are blueprints, and objects are created from these blueprints.  Multiple objects can be created from the same class, each with its own unique state but sharing the same behavior defined by the class.

3.  **What is Encapsulation? Why is it important in OOP?**
    *   **Answer:** Encapsulation is the bundling of data (attributes) and methods that operate on that data into a single unit, called a class. It also involves hiding the internal implementation details of the class from the outside world and providing controlled access to the data through well-defined interfaces (methods).
    *   **Importance of Encapsulation:**
        *   **Data Hiding and Protection:** Prevents direct, unauthorized access to an object's internal data. Data can only be accessed and modified through the class's methods, allowing for controlled access and data validation.
        *   **Modularity and Code Organization:**  Organizes code into self-contained units (classes), making code more modular, easier to understand, and maintain.
        *   **Abstraction and Reduced Complexity:** Hides complex implementation details, presenting a simplified interface to the user. Users interact with objects through methods without needing to know the internal workings.
        *   **Flexibility and Maintainability:**  Implementation details of a class can be changed without affecting the code that uses the class, as long as the public interface (methods) remains the same. This promotes flexibility and easier code maintenance.
        *   **Code Reusability:** Encapsulated classes can be easily reused in different parts of the program or in other programs as self-contained modules.

4.  **What is Abstraction? How is it achieved in OOP?**
    *   **Answer:** Abstraction is the process of simplifying complex systems by modeling classes based on their essential characteristics and ignoring or hiding unnecessary details. It focuses on "what" an object does rather than "how" it does it.
    *   **How Abstraction is Achieved in OOP:**
        *   **Abstract Classes:** Classes that cannot be instantiated directly and may contain abstract methods (methods without implementation). Abstract classes define a common interface for their subclasses and provide a partial implementation. Subclasses must provide concrete implementations for abstract methods.
        *   **Interfaces:** Define a contract or a set of methods that classes implementing the interface must provide. Interfaces specify "what" methods a class should have but not "how" they are implemented. Classes can implement multiple interfaces.
        *   **Access Modifiers:**  `public`, `private`, `protected` access modifiers help control the visibility of class members (attributes and methods), hiding internal implementation details and exposing only necessary parts to the outside.
        *   **Focus on Essential Features:** During class design, focusing on essential attributes and behaviors relevant to the problem domain and ignoring less important details.

5.  **What is Inheritance? Explain the benefits of inheritance.**
    *   **Answer:** Inheritance is a fundamental OOP principle that allows a new class (subclass or derived class) to inherit properties and behaviors (attributes and methods) from an existing class (superclass or base class). It establishes an "is-a" relationship (e.g., "a Car *is a* Vehicle").
    *   **Benefits of Inheritance:**
        *   **Code Reusability:** Subclasses inherit code from the superclass, reducing code duplication. Common attributes and methods can be defined in the superclass and reused by multiple subclasses.
        *   **Extensibility:**  New subclasses can be created to extend the functionality of existing classes without modifying the superclass directly.  New behaviors can be added in subclasses while inheriting core functionalities.
        *   **Organization and Hierarchy:** Organizes classes into a hierarchy, representing "is-a" relationships and making code more structured and understandable.
        *   **Polymorphism Enablement:** Inheritance is crucial for achieving runtime polymorphism (method overriding). Subclasses can override methods of the superclass to provide specialized implementations.
        *   **Abstraction:** Superclasses can define abstract methods or interfaces, forcing subclasses to implement specific behaviors, promoting abstraction and interface-based programming.

6.  **What is Polymorphism? Explain different types of polymorphism.**
    *   **Answer:** Polymorphism (meaning "many forms") is the ability of an object or a reference variable to take on many forms. It allows objects of different classes to be treated as objects of a common type and respond differently to the same method call.
    *   **Types of Polymorphism:**
        *   **Compile-Time Polymorphism (Static Polymorphism or Method Overloading):** Achieved through method overloading. Multiple methods in the same class have the same name but different parameter lists (different number, types, or order of parameters).  The compiler decides which method to call based on the method signature at compile time.
        *   **Runtime Polymorphism (Dynamic Polymorphism or Method Overriding):** Achieved through method overriding (in inheritance) and interfaces.  A subclass overrides a method of its superclass with the same signature. The actual method to be executed is determined at runtime based on the actual object type (not the reference type). This is also known as dynamic method dispatch.

**II. Classes and Objects in Java:**

7.  **How do you define a class in Java? What are the components of a class?**
    *   **Answer:** In Java, you define a class using the `class` keyword followed by the class name, and curly braces `{}` to enclose the class body.
    *   **Components of a Class:**
        *   **Fields (Attributes or Instance Variables):** Variables that hold the state of an object. They are declared inside the class but outside any method.
        *   **Methods (Behaviors or Functions):**  Blocks of code that define the actions or operations an object can perform. Methods operate on the object's data (fields).
        *   **Constructors:** Special methods that are used to initialize objects of the class when they are created. They have the same name as the class and no return type.
        *   **Inner Classes (Nested Classes):** Classes defined inside another class.
        *   **Static Initializers and Instance Initializers:** Blocks of code used to initialize static and instance variables respectively.
        *   **Annotations:** Metadata that provide information about the class to the compiler or JVM (e.g., `@Override`, `@Deprecated`).
        *   **Comments:**  Explanatory text within the code (e.g., `// single-line comment`, `/* multi-line comment */`, `/** Javadoc comment */`).

    ```java
    public class Dog { // Class definition
        // Fields (instance variables)
        String name;
        String breed;
        int age;

        // Constructor
        public Dog(String name, String breed, int age) {
            this.name = name;
            this.breed = breed;
            this.age = age;
        }

        // Method
        public void bark() {
            System.out.println("Woof!");
        }
    }
    ```

8.  **How do you create an object of a class in Java? Explain the role of the `new` keyword and constructors.**
    *   **Answer:** You create an object of a class in Java using the `new` keyword followed by a call to a constructor of the class.
    *   **Role of `new` Keyword:**
        *   The `new` keyword is used to allocate memory for a new object of the specified class on the heap (dynamic memory).
        *   It creates an instance of the class in memory.
    *   **Role of Constructor:**
        *   After memory allocation, the `new` keyword calls the constructor of the class.
        *   The constructor is responsible for initializing the object's state (instance variables). It sets initial values for the object's attributes.
        *   If no constructor is explicitly defined in a class, Java provides a default no-argument constructor.

    ```java
    // Class definition (Dog class from previous example)

    public class Main {
        public static void main(String[] args) {
            // Creating an object of the Dog class using the new keyword and constructor
            Dog myDog = new Dog("Buddy", "Golden Retriever", 3);
            Dog anotherDog = new Dog("Lucy", "Labrador", 5);

            // Accessing object's attributes and methods
            System.out.println("My dog's name: " + myDog.name); // Accessing attribute
            myDog.bark(); // Calling method
        }
    }
    ```

9.  **What is a constructor in Java? What are the different types of constructors?**
    *   **Answer:** A constructor is a special method in a class that is automatically called when an object of that class is created using the `new` keyword. It has the same name as the class and no return type (not even `void`). Constructors are used to initialize the object's state (instance variables).
    *   **Types of Constructors in Java:**
        *   **Default Constructor (No-Argument Constructor):** A constructor with no parameters. If you don't explicitly define any constructor in your class, Java compiler automatically provides a default constructor. It initializes instance variables to their default values (0 for numeric types, `false` for boolean, `null` for object references).
        *   **Parameterized Constructor:** A constructor that accepts one or more parameters. Used to initialize the object's attributes with specific values provided during object creation. You can have multiple parameterized constructors (constructor overloading).
        *   **Copy Constructor:** A constructor that creates a new object as a copy of an existing object of the same class. Not automatically provided by Java, you need to define it if needed. Less common in Java than in C++.

    ```java
    public class Book {
        String title;
        String author;

        // Default Constructor (No-Argument Constructor)
        public Book() {
            title = "Unknown Title";
            author = "Unknown Author";
        }

        // Parameterized Constructor
        public Book(String title, String author) {
            this.title = title;
            this.author = author;
        }

        // Example of another Parameterized Constructor (Constructor Overloading)
        public Book(String title) {
            this.title = title;
            this.author = "Unknown Author";
        }

        // ... methods ...
    }
    ```

10. **What is the difference between a constructor and a method in Java?**
    *   **Answer:**
        *   **Constructor:**
            *   Purpose: To initialize objects of a class when they are created.
            *   Name: Has the same name as the class.
            *   Return Type: No return type (not even `void`).
            *   Invocation: Automatically invoked when an object is created using `new`. Cannot be called explicitly like regular methods.
            *   Invocation Time: Called only once per object creation.
        *   **Method:**
            *   Purpose: To define the behavior or actions an object can perform.
            *   Name: Can have any valid method name (following Java naming conventions).
            *   Return Type: Must have a return type (can be `void` if it doesn't return a value).
            *   Invocation: Called explicitly by using the object reference and method name (e.g., `object.methodName()`).
            *   Invocation Time: Can be called multiple times on an object as needed.

11. **What is the `this` keyword in Java? How is it used?**
    *   **Answer:** The `this` keyword in Java is a reference variable that refers to the current object. It is used to access instance variables and methods of the current object within the class itself.
    *   **Uses of `this` Keyword:**
        *   **Referring to Instance Variables:** When instance variable names and local variable or parameter names are the same, `this` is used to distinguish between them. `this.variableName` refers to the instance variable, while `variableName` refers to the local variable or parameter.
        *   **Calling One Constructor from Another (Constructor Chaining):** Within a constructor, `this()` can be used to call another constructor of the same class. This is called constructor chaining and is useful for code reuse in constructors. `this()` call must be the first statement in the constructor.
        *   **Returning Current Object from Method:** `this` can be returned as the return value from a method. This is often used in method chaining patterns (fluent interfaces).
        *   **Passing Current Object as Argument:** `this` can be passed as an argument to another method call within the same class or to a method in another class.

    ```java
    public class Person {
        String name;
        int age;

        // Constructor using 'this' to differentiate between instance variable and parameter names
        public Person(String name, int age) {
            this.name = name; // this.name refers to instance variable, name refers to parameter
            this.age = age;   // this.age refers to instance variable, age refers to parameter
        }

        // Method using 'this' to access instance variable
        public void displayInfo() {
            System.out.println("Name: " + this.name + ", Age: " + this.age); // this.name and this.age access instance variables
        }

        // Constructor chaining using this()
        public Person() {
            this("Default Name", 0); // Calls the parameterized constructor with default values
        }
    }
    ```

12. **What are access modifiers in Java? Explain `public`, `private`, `protected`, and default access modifiers.**
    *   **Answer:** Access modifiers in Java are keywords that control the visibility or accessibility of class members (variables, methods, constructors, inner classes). They define where and how these members can be accessed from.
    *   **Access Modifiers:**
        *   **`public`:**  Widest access level. Members declared `public` are accessible from anywhere - within the same class, from subclasses (in the same or different packages), and from any other class in any package.
        *   **`private`:**  Most restrictive access level. Members declared `private` are accessible only within the same class in which they are declared. They are not accessible from subclasses or any other classes, even in the same package. Used for strong encapsulation and data hiding.
        *   **`protected`:** Members declared `protected` are accessible within the same package and by subclasses (even if they are in a different package). Not accessible from non-subclasses in a different package. Provides package-level access and inheritance-level access.
        *   **Default (Package-Private or No Modifier):** When no access modifier is explicitly specified, it's called default access. Members with default access are accessible only within the same package. Not accessible from subclasses in a different package or from any other classes in a different package. Provides package-level access.

    | Modifier    | Class | Package | Subclass (Same Package) | Subclass (Different Package) | World (Anywhere) |
    |-------------|-------|---------|-------------------------|-----------------------------|-----------------|
    | `public`    | Yes   | Yes     | Yes                     | Yes                         | Yes             |
    | `protected` | Yes   | Yes     | Yes                     | Yes                         | No              |
    | Default     | Yes   | Yes     | Yes                     | No                          | No              |
    | `private`   | Yes   | No      | No                      | No                          | No              |

13. **What are static variables and static methods in Java? How do they differ from instance variables and methods?**
    *   **Answer:**
        *   **Static Variables (Class Variables):**
            *   Declared using the `static` keyword.
            *   Belong to the class itself, not to any specific object of the class.
            *   Shared among all objects of the class. There is only one copy of a static variable per class, regardless of how many objects are created.
            *   Accessed using the class name (e.g., `ClassName.staticVariable`). Can also be accessed through object references, but not recommended (less clear).
            *   Initialized when the class is loaded into memory, before any objects are created.
        *   **Static Methods (Class Methods):**
            *   Declared using the `static` keyword.
            *   Belong to the class itself, not to any specific object.
            *   Can be called directly using the class name (e.g., `ClassName.staticMethod()`). Can also be called through object references, but not recommended.
            *   Cannot access instance variables or instance methods directly because static methods don't have a `this` reference to a specific object instance. They can access static variables and other static methods.
        *   **Instance Variables (Non-Static Variables):**
            *   Declared without the `static` keyword.
            *   Belong to each object of the class. Each object has its own copy of instance variables.
            *   Accessed using object references (e.g., `object.instanceVariable`).
            *   Initialized when an object is created using a constructor.
        *   **Instance Methods (Non-Static Methods):**
            *   Declared without the `static` keyword.
            *   Operate on specific objects of the class. They have access to instance variables of the object through the `this` reference.
            *   Called using object references (e.g., `object.instanceMethod()`).
            *   Can access both instance variables and static variables.

    ```java
    public class Counter {
        static int count = 0; // Static variable (class variable)
        int instanceCount = 0; // Instance variable

        public Counter() {
            count++; // Increment static variable
            instanceCount++; // Increment instance variable
        }

        public static int getCount() { // Static method (class method)
            return count; // Can access static variable
            // return instanceCount; // Error: Cannot access instance variable from static method
        }

        public void displayInstanceCount() { // Instance method
            System.out.println("Instance Count: " + instanceCount); // Can access instance variable
            System.out.println("Static Count: " + count); // Can also access static variable
        }
    }
    ```

**III. Inheritance in Java:**

14. **What is inheritance in Java? Explain different types of inheritance supported in Java.**
    *   **Answer:** Inheritance in Java is a mechanism that allows a class (subclass) to inherit properties and behaviors from another class (superclass). It's a way to create a hierarchy of classes and promote code reusability.
    *   **Types of Inheritance Supported in Java:**
        *   **Single Inheritance:** A subclass inherits from only one superclass. Java directly supports single inheritance for classes.  *Example: Class `Dog` inheriting from class `Animal`.*
        *   **Multilevel Inheritance:** A subclass inherits from a superclass, and then another class inherits from that subclass, forming a chain of inheritance. Java supports multilevel inheritance. *Example: Class `GermanShepherd` inheriting from `Dog`, which inherits from `Animal`.*
        *   **Hierarchical Inheritance:** Multiple subclasses inherit from a single superclass. Java supports hierarchical inheritance. *Example: Classes `Dog`, `Cat`, `Bird` all inheriting from `Animal`.*
        *   **Multiple Inheritance:** A class inheriting from multiple superclasses. **Java does NOT directly support multiple inheritance for classes** due to the "diamond problem" and complexity. However, Java supports multiple inheritance through **interfaces**. A class can implement multiple interfaces.

15. **What is the `extends` keyword used for in Java?**
    *   **Answer:** The `extends` keyword in Java is used to establish an inheritance relationship between two classes. It is used in the class declaration of a subclass to specify the superclass it inherits from.

    ```java
    class Animal { // Superclass
        // ...
    }

    class Dog extends Animal { // Subclass 'Dog' inherits from 'Animal'
        // ...
    }
    ```

16. **What is method overriding in Java? How is it related to inheritance?**
    *   **Answer:** Method overriding is a feature in Java that allows a subclass to provide a specific implementation for a method that is already defined in its superclass. It's a key aspect of runtime polymorphism. Method overriding is only possible in an inheritance hierarchy (subclass overriding a method from its superclass).
    *   **Relationship to Inheritance:** Method overriding is a core concept of inheritance. When a subclass inherits a method from its superclass, it can choose to *override* that method to provide its own specialized behavior. The overridden method in the subclass must have the same method signature (name, parameters, return type) as the method in the superclass.

    ```java
    class Animal {
        public void makeSound() {
            System.out.println("Generic animal sound");
        }
    }

    class Dog extends Animal {
        @Override // @Override annotation is good practice for overriding
        public void makeSound() { // Method overriding
            System.out.println("Woof!"); // Dog-specific implementation
        }
    }

    public class Main {
        public static void main(String[] args) {
            Animal animal = new Animal();
            Dog dog = new Dog();

            animal.makeSound(); // Output: Generic animal sound
            dog.makeSound();    // Output: Woof! (Dog's overridden method is called)

            Animal animalRef = dog; // Animal reference pointing to a Dog object (Polymorphism)
            animalRef.makeSound();  // Output: Woof! (Runtime polymorphism - Dog's method is called based on object type)
        }
    }
    ```

17. **What is the `super` keyword in Java? How is it used in inheritance?**
    *   **Answer:** The `super` keyword in Java is a reference variable that refers to the superclass object within a subclass. It is used to access members (methods and variables) of the superclass from within the subclass.
    *   **Uses of `super` Keyword in Inheritance:**
        *   **Calling Superclass Constructor:** `super()` is used to call the constructor of the superclass from within a subclass constructor. It must be the first statement in the subclass constructor. Used to initialize superclass members before subclass-specific initialization.
        *   **Accessing Overridden Superclass Methods:** `super.methodName()` is used to call the overridden method of the superclass from within the subclass method. Useful when you want to extend the functionality of the superclass method in the subclass, rather than completely replacing it.
        *   **Accessing Superclass Variables:** `super.variableName` can be used to access superclass instance variables (if they are accessible - e.g., `protected` or `public`) from within the subclass.

    ```java
    class Animal {
        String name;
        public Animal(String name) {
            this.name = name;
        }
        public void makeSound() {
            System.out.println("Generic animal sound");
        }
    }

    class Dog extends Animal {
        String breed;
        public Dog(String name, String breed) {
            super(name); // Calling superclass constructor using super() - must be first statement
            this.breed = breed; // Initializing subclass-specific attribute
        }

        @Override
        public void makeSound() {
            super.makeSound(); // Calling superclass's makeSound() using super.methodName()
            System.out.println("Woof!"); // Adding subclass-specific sound
        }

        public void displayInfo() {
            System.out.println("Name: " + super.name + ", Breed: " + breed); // Accessing superclass variable using super.variableName
        }
    }
    ```

18. **What is the difference between method overriding and method overloading?**
    *   **Answer:**
        *   **Method Overriding:**
            *   Polymorphism Type: Runtime Polymorphism (Dynamic Polymorphism).
            *   Relationship: Occurs in inheritance (between superclass and subclass).
            *   Method Signature: Same method name and same parameter list (signature) in both superclass and subclass. Return type must be the same or covariant (subclass return type).
            *   Purpose: Subclass provides a specific implementation for a method already defined in the superclass.
            *   Resolution: Method to be executed is decided at runtime based on the actual object type (dynamic method dispatch).
        *   **Method Overloading:**
            *   Polymorphism Type: Compile-Time Polymorphism (Static Polymorphism).
            *   Relationship: Occurs within the same class.
            *   Method Signature: Same method name but different parameter lists (different number, types, or order of parameters). Return type can be the same or different (but not just return type difference alone).
            *   Purpose: To provide multiple methods in the same class with the same name but different ways to be called (different inputs).
            *   Resolution: Method to be executed is decided at compile time based on the method signature used in the method call.

    | Feature             | Method Overriding                               | Method Overloading                                  |
    |----------------------|-------------------------------------------------|------------------------------------------------------|
    | Polymorphism Type   | Runtime Polymorphism (Dynamic)                  | Compile-Time Polymorphism (Static)                     |
    | Relationship        | Inheritance (Superclass and Subclass)           | Within the same class                                |
    | Method Signature    | Same name, same parameters, same/covariant return type | Same name, different parameter lists (signature)        |
    | Method Resolution   | Runtime (Dynamic Method Dispatch)              | Compile Time                                         |
    | Purpose             | Subclass provides specialized implementation     | Provide multiple methods with same name, different inputs |

19. **Can you inherit from multiple classes in Java? Why or why not? How do you achieve similar functionality? (Interfaces)**
    *   **Answer:** No, Java does not support multiple inheritance for classes directly. A class in Java can extend (inherit from) only one superclass.
    *   **Why Multiple Inheritance is Not Directly Supported (Diamond Problem):**
        *   **Diamond Problem (Ambiguity):** If class C inherits from class B1 and class B2, and both B1 and B2 inherit from class A, and if class A has a method `methodX()`, and both B1 and B2 do not override `methodX()`, but class C *does* override `methodX()`.  If a class D then inherits from both B1 and B2, and calls `methodX()` through a D object, which version of `methodX()` should be called – the one from B1's inheritance path or B2's? This ambiguity is known as the diamond problem.
        *   **Complexity and Design Issues:** Multiple inheritance can lead to complex class hierarchies, increased complexity in method resolution, and potential design issues.
    *   **How to Achieve Similar Functionality (Using Interfaces):**
        *   **Interfaces in Java provide a form of multiple inheritance of *type* (not implementation).** A class can implement multiple interfaces.
        *   **Interfaces define contracts (sets of methods) but do not provide implementation.** Classes implementing interfaces must provide their own implementations for all methods declared in the interface.
        *   **By implementing multiple interfaces, a class can adhere to multiple contracts and inherit multiple types (interfaces), effectively achieving a form of multiple inheritance of type, without the ambiguities of multiple inheritance of implementation.**

    ```java
    interface Flyable {
        void fly();
    }

    interface Swimmable {
        void swim();
    }

    class Duck implements Flyable, Swimmable { // Duck implements multiple interfaces
        @Override
        public void fly() {
            System.out.println("Duck is flying");
        }

        @Override
        public void swim() {
            System.out.println("Duck is swimming");
        }
    }
    ```

**IV. Polymorphism in Java:**

20. **What is polymorphism in Java? Explain compile-time polymorphism (method overloading) and runtime polymorphism (method overriding).**
    *   **Answer:** (Refer to answer in Q6 - What is Polymorphism? Explain different types of polymorphism.) Polymorphism is the ability of an object to take on many forms.

21. **Explain method overloading in Java with an example.**
    *   **Answer:** Method overloading is a type of compile-time polymorphism where a class can have multiple methods with the same name but different parameter lists (signatures). The compiler determines which overloaded method to call based on the arguments passed in the method call.

    ```java
    class Calculator {
        // Method to add two integers
        public int add(int num1, int num2) {
            return num1 + num2;
        }

        // Overloaded method to add three integers (same name 'add', different parameter list)
        public int add(int num1, int num2, int num3) {
            return num1 + num2 + num3;
        }

        // Overloaded method to add two doubles (same name 'add', different parameter list - different parameter types)
        public double add(double num1, double num2) {
            return num1 + num2;
        }
    }

    public class Main {
        public static void main(String[] args) {
            Calculator calc = new Calculator();

            System.out.println(calc.add(2, 3));      // Calls add(int, int) - Output: 5
            System.out.println(calc.add(2, 3, 4));   // Calls add(int, int, int) - Output: 9
            System.out.println(calc.add(2.5, 3.5)); // Calls add(double, double) - Output: 6.0
        }
    }
    ```

22. **Explain method overriding in Java with an example.**
    *   **Answer:** Method overriding is a type of runtime polymorphism where a subclass provides a specific implementation for a method that is already defined in its superclass. The method in the subclass must have the same signature as the method in the superclass.

    ```java
    class Vehicle {
        public void startEngine() {
            System.out.println("Vehicle engine started");
        }
    }

    class Car extends Vehicle {
        @Override // @Override annotation is good practice
        public void startEngine() { // Method overriding
            System.out.println("Car engine started (ignition key)"); // Car-specific implementation
        }
    }

    class Motorcycle extends Vehicle {
        @Override
        public void startEngine() { // Method overriding
            System.out.println("Motorcycle engine started (push button)"); // Motorcycle-specific implementation
        }
    }

    public class Main {
        public static void main(String[] args) {
            Vehicle vehicle = new Vehicle();
            Car car = new Car();
            Motorcycle motorcycle = new Motorcycle();

            vehicle.startEngine();    // Output: Vehicle engine started
            car.startEngine();        // Output: Car engine started (ignition key)
            motorcycle.startEngine(); // Output: Motorcycle engine started (push button)

            Vehicle vehicleRefCar = car; // Polymorphism - Vehicle reference to Car object
            vehicleRefCar.startEngine(); // Output: Car engine started (ignition key) - Runtime polymorphism

            Vehicle vehicleRefMotorcycle = motorcycle; // Polymorphism - Vehicle reference to Motorcycle object
            vehicleRefMotorcycle.startEngine(); // Output: Motorcycle engine started (push button) - Runtime polymorphism
        }
    }
    ```

23. **How is runtime polymorphism achieved in Java? (Dynamic method dispatch)**
    *   **Answer:** Runtime polymorphism in Java is achieved through a mechanism called **dynamic method dispatch** (or late binding).
    *   **Dynamic Method Dispatch Process:**
        1.  **Method Call through Reference Variable:** When a method is called through a reference variable (e.g., `animalRef.makeSound()`), the JVM does not decide which method to call at compile time (based on the reference type `Animal`).
        2.  **Object Type at Runtime:** Instead, the JVM determines the actual type of the object that the reference variable is pointing to *at runtime*. In the example `Animal animalRef = dog;`, `animalRef` is of type `Animal`, but at runtime, it points to an object of type `Dog`.
        3.  **Method Invocation based on Object Type:** The JVM then looks for the method to be called (`makeSound()`) in the class of the *actual object* (`Dog` in this case), starting from the object's class and moving up the inheritance hierarchy if necessary.
        4.  **Overridden Method Execution:** If the method is overridden in the object's class (like `makeSound()` in `Dog` overriding `Animal`'s `makeSound()`), the JVM executes the overridden method defined in the object's class (`Dog`'s `makeSound()`).
        5.  **Superclass Method Execution (if not overridden):** If the method is not overridden in the object's class, the JVM executes the method from the nearest superclass in the inheritance hierarchy that provides an implementation.
    *   **Key Factors for Runtime Polymorphism:**
        *   **Inheritance:** Runtime polymorphism relies on inheritance and method overriding.
        *   **Method Overriding:** Subclasses must override methods of the superclass to provide specialized implementations.
        *   **Reference Variable of Superclass Type:** Method calls are typically made through a reference variable of the superclass type that can point to objects of different subclass types.
        *   **Dynamic Binding:** The binding of method call to the actual method implementation happens at runtime, not compile time.

24. **What is the purpose of the `@Override` annotation in Java?**
    *   **Answer:** The `@Override` annotation in Java is a marker annotation that is used to indicate that a method in a subclass is intended to override a method in its superclass. It is optional but highly recommended for method overriding.
    *   **Purpose and Benefits of `@Override` Annotation:**
        *   **Compiler Error Detection:** The most important purpose is to enable the Java compiler to check if you are actually overriding a superclass method correctly. If you use `@Override` and the method signature in the subclass does not exactly match a method signature in the superclass (e.g., different parameter types, different name, return type), the compiler will generate a compile-time error. This helps catch errors early and prevents accidental method overloading when you intend to override.
        *   **Code Readability and Maintainability:** `@Override` makes the code more readable and understandable by explicitly indicating that a method is intended to override a superclass method. It makes it clear to other developers (and yourself in the future) that this method is part of an inheritance and polymorphism relationship.
        *   **Refactoring Safety:** When refactoring code in the superclass (e.g., renaming or changing parameters of a method), the compiler will detect if any `@Override` annotations in subclasses are now invalid due to signature mismatches, helping to maintain code consistency during refactoring.
        *   **Documentation:** `@Override` acts as a form of documentation, clearly stating the intention of method overriding.

25. **How is abstraction achieved in Java? Explain abstract classes and interfaces.**
    *   **Answer:** (Refer to answer in Q4 - What is Abstraction? How is it achieved in OOP?) Abstraction in Java is primarily achieved using abstract classes and interfaces.

26. **What is an abstract class in Java? Can you create an object of an abstract class?**
    *   **Answer:** An abstract class in Java is a class that is declared with the `abstract` keyword. It is designed to be a base class for other classes and cannot be instantiated directly (you cannot create objects of an abstract class). Abstract classes can contain both abstract methods (methods without implementation) and concrete methods (methods with implementation).
    *   **Key Features of Abstract Classes:**
        *   **`abstract` Keyword:** Declared using the `abstract` keyword in the class definition.
        *   **Abstract Methods (Optional):** Can contain abstract methods, which are declared with the `abstract` keyword and have no method body (no implementation). Abstract methods must be implemented by concrete subclasses.
        *   **Concrete Methods (Optional):** Can contain concrete methods with full implementations, which are inherited by subclasses.
        *   **Constructors:** Abstract classes can have constructors, which are called when constructors of concrete subclasses are invoked (through `super()` call).
        *   **Cannot be Instantiated:** You cannot create objects (instances) of an abstract class directly using the `new` keyword. Abstract classes are meant to be extended (subclassed).
        *   **Purpose:** To provide a common base class with some shared implementation and to define a common interface (through abstract methods) that subclasses must implement.

    ```java
    abstract class Shape { // Abstract class
        String color;

        public Shape(String color) {
            this.color = color;
        }

        // Abstract method (no implementation) - subclasses must implement this
        abstract double getArea();

        // Concrete method (with implementation) - inherited by subclasses
        public String getColor() {
            return color;
        }
    }

    class Circle extends Shape { // Concrete subclass extending abstract class
        double radius;
        public Circle(String color, double radius) {
            super(color); // Calling superclass (Shape) constructor
            this.radius = radius;
        }

        @Override // Implementing the abstract method from Shape
        double getArea() {
            return Math.PI * radius * radius;
        }
    }

    public class Main {
        public static void main(String[] args) {
            // Shape shape = new Shape("Red"); // Error: Cannot create an instance of an abstract class

            Circle circle = new Circle("Blue", 5.0); // Creating object of concrete subclass
            System.out.println("Circle Area: " + circle.getArea()); // Calling implemented abstract method
        }
    }
    ```

27. **What is an interface in Java? How is it different from an abstract class?**
    *   **Answer:** An interface in Java is a blueprint of a class. It is a contract that specifies a set of methods that implementing classes must provide. Interfaces are declared using the `interface` keyword. They are used to achieve abstraction and multiple inheritance of type in Java.
    *   **Key Features of Interfaces:**
        *   **`interface` Keyword:** Declared using the `interface` keyword.
        *   **Abstract Methods (by default):** Interfaces primarily contain abstract methods (methods without implementation).  Methods in interfaces are implicitly `public` and `abstract` (even if not explicitly declared). In Java 8 and later, interfaces can also have `default` methods (with implementation) and `static` methods.
        *   **Constants (Optional):** Interfaces can declare constants (static final variables), which are implicitly `public static final`.
        *   **No Instance Variables (except constants):** Interfaces cannot have instance variables (non-static fields).
        *   **No Constructors:** Interfaces cannot have constructors.
        *   **Cannot be Instantiated:** You cannot create objects (instances) of an interface directly. Interfaces are meant to be implemented by classes.
        *   **Multiple Inheritance of Type:** A class can implement multiple interfaces (using `implements` keyword).

    *   **Differences between Abstract Class and Interface:**

    | Feature             | Abstract Class                                    | Interface                                         |
    |----------------------|----------------------------------------------------|----------------------------------------------------|
    | Keyword             | `abstract class`                                   | `interface`                                        |
    | Instantiation       | Cannot be instantiated (abstract class)            | Cannot be instantiated (interface)                 |
    | Inheritance         | Class `extends` only one abstract class (single inheritance of class) | Class `implements` multiple interfaces (multiple inheritance of type) |
    | Methods             | Can have both abstract and concrete methods         | Primarily abstract methods (until Java 8), can have default and static methods since Java 8 |
    | Instance Variables  | Can have instance variables (fields)               | Cannot have instance variables (except constants)     |
    | Constructors        | Can have constructors                               | Cannot have constructors                            |
    | Access Modifiers    | Members can have any access modifier (`public`, `protected`, `private`, default) | Methods are implicitly `public abstract` (or `default`, `static` in Java 8+), constants are implicitly `public static final` |
    | Purpose             | Provide a common base class with partial implementation and interface | Define a contract, specify a set of methods that implementing classes must provide, achieve multiple inheritance of type |
    | "Is-a" vs. "Can-do" | Often represents an "is-a" relationship (e.g., `Animal` is an abstract class, `Dog` is an `Animal`) | Represents a "can-do" or "capability" relationship (e.g., `Flyable` interface, `Bird` can be `Flyable`) |

28. **Can a class implement multiple interfaces in Java?**
    *   **Answer:** Yes, a class in Java can implement multiple interfaces. This is a key feature of interfaces and is Java's way of supporting a form of multiple inheritance (multiple inheritance of type).
    *   **How to Implement Multiple Interfaces:** A class uses the `implements` keyword followed by a comma-separated list of interface names in its class declaration. The class must provide concrete implementations for all abstract methods declared in *all* the interfaces it implements.

    ```java
    interface InterfaceA {
        void methodA();
    }

    interface InterfaceB {
        void methodB();
    }

    class MyClass implements InterfaceA, InterfaceB { // Implements both InterfaceA and InterfaceB
        @Override
        public void methodA() {
            System.out.println("Implementation of methodA from InterfaceA");
        }

        @Override
        public void methodB() {
            System.out.println("Implementation of methodB from InterfaceB");
        }
    }
    ```

29. **How is encapsulation achieved in Java? Explain the role of access modifiers in encapsulation.**
    *   **Answer:** Encapsulation in Java is primarily achieved through **access modifiers**. Access modifiers control the visibility and accessibility of class members (variables and methods), allowing you to hide internal implementation details and protect data, which are key aspects of encapsulation.
    *   **Role of Access Modifiers in Encapsulation:**
        *   **`private` Modifier (Data Hiding):** The `private` access modifier is the most important tool for encapsulation. By declaring instance variables (`fields`) as `private`, you restrict direct access to them from outside the class. This hides the internal data representation of the object.
        *   **`public` Modifier (Controlled Access through Methods):**  `public` access modifier for methods provides a well-defined public interface for interacting with objects. Public methods act as gateways to access and manipulate the object's data in a controlled manner.  You define `public` methods (like getters and setters) to provide controlled access to `private` data.
        *   **`protected` and Default Modifiers (Package-Level and Inheritance-Level Encapsulation):** `protected` and default access modifiers provide intermediate levels of encapsulation, controlling access within packages and inheritance hierarchies, further contributing to modularity and controlled access.
        *   **Example:**

        ```java
        class BankAccount {
            private double balance; // Private instance variable - Encapsulated (data hiding)

            public BankAccount(double initialBalance) {
                this.balance = initialBalance;
            }

            public double getBalance() { // Public getter method - Controlled access to balance
                return balance;
            }

            public void deposit(double amount) { // Public method to modify balance in a controlled way
                if (amount > 0) {
                    balance += amount;
                }
            }

            public void withdraw(double amount) { // Public method with validation
                if (amount > 0 && amount <= balance) {
                    balance -= amount;
                } else {
                    System.out.println("Insufficient balance or invalid amount.");
                }
            }
        }
        ```
        In this example, `balance` is `private`, ensuring data hiding. Access and modifications are only allowed through `public` methods (`getBalance()`, `deposit()`, `withdraw()`), which provide controlled access and can include validation logic, thus achieving encapsulation.

33. **What is exception handling in Java? Why is it important?**

34. **Explain the `try-catch-finally` block in Java exception handling.**
    *   **Answer:** The `try-catch-finally` block is the fundamental construct for exception handling in Java.
    *   **Components:**
        *   **`try` Block:** Encloses the code that might potentially throw an exception. You place the code that you want to monitor for exceptions within the `try` block.
        *   **`catch` Block(s):** Follows the `try` block. One or more `catch` blocks can be defined to handle specific types of exceptions. Each `catch` block specifies the type of exception it can handle and contains code to execute if an exception of that type occurs in the `try` block.
        *   **`finally` Block (Optional):**  An optional block that follows the `try` and `catch` blocks. Code in the `finally` block is always executed, regardless of whether an exception occurred in the `try` block or whether a `catch` block was executed. Used for cleanup operations (e.g., closing resources like files or database connections) that must be performed whether an exception occurred or not.

    ```java
    try {
        // Code that might throw an exception (e.g., file I/O, network operation, division by zero)
        int result = 10 / 0; // This will throw an ArithmeticException
        System.out.println("This line will not be executed if exception occurs");
    } catch (ArithmeticException e) {
        // Catch block to handle ArithmeticException
        System.err.println("Arithmetic Exception caught: " + e.getMessage());
        // Code to handle the exception (e.g., log error, display message, attempt recovery)
    } catch (Exception e) { // Catch block to handle other types of Exceptions (more general)
        System.err.println("Some other Exception caught: " + e.getMessage());
    } finally {
        // Finally block (optional) - code that always executes
        System.out.println("Finally block executed");
        // Cleanup code (e.g., close resources)
    }

    System.out.println("Program continues after try-catch-finally block"); // Program execution continues
    ```

35. **What are checked and unchecked exceptions in Java? Give examples.**
    *   **Answer:** Exceptions in Java are categorized into checked and unchecked exceptions, based on whether the compiler forces you to handle them explicitly.
        *   **Checked Exceptions (Compile-Time Exceptions):**
            *   Exceptions that the compiler *forces* you to handle (either using `try-catch` block or by declaring the exception in the method's `throws` clause).
            *   Represent exceptional conditions that a well-written application should anticipate and recover from.
            *   Checked exceptions are subclasses of `Exception` class, but *not* subclasses of `RuntimeException` or `Error`.
            *   *Examples:* `IOException` (e.g., file not found, network error), `SQLException` (database error), `ClassNotFoundException`, `InterruptedException`.
        *   **Unchecked Exceptions (Runtime Exceptions):**
            *   Exceptions that the compiler *does not* force you to handle. You can choose to handle them using `try-catch`, but it's not mandatory.
            *   Represent programming errors or unexpected conditions that are usually due to code defects or logic errors.
            *   Unchecked exceptions are subclasses of `RuntimeException` or `Error`.
            *   *Examples:* `ArithmeticException` (e.g., division by zero), `NullPointerException` (accessing a null reference), `ArrayIndexOutOfBoundsException`, `IllegalArgumentException`, `ClassCastException`.
        *   **`Error`s:** Another category of throwable, but typically represent serious system-level errors (like `OutOfMemoryError`, `StackOverflowError`) that are usually unrecoverable and indicate severe problems with the JVM or system itself. Handling `Error`s is generally not recommended; focus on preventing them.

37. **What are Generics in Java? Why are generics used?**
    *   **Answer:** Generics in Java allow you to parameterize types. They enable you to write classes, interfaces, and methods that can work with different types of objects while providing compile-time type safety. Generics introduce type parameters to classes, interfaces, and methods, allowing you to specify the type of data they will operate on when they are used.
    *   **Why Generics are Used:**
        *   **Type Safety:** Generics provide compile-time type safety. The compiler checks type constraints at compile time, preventing runtime `ClassCastException` errors that can occur with non-generic collections when dealing with mixed types.
        *   **Code Reusability:** Generics allow you to write code that is reusable with different types. You can create generic classes, interfaces, and methods that work with various data types without needing to write separate code for each type.
        *   **Improved Readability:** Generics make code more readable by making type information explicit. Type parameters in generic classes and methods clearly indicate the types they are intended to work with.
        *   **Type Erasure:** Java generics are implemented using type erasure. At runtime, generic type information is erased, and generic types behave like raw types (like `Object`). This ensures backward compatibility with older Java versions.

    ```java
    import java.util.ArrayList;
    import java.util.List;

    public class GenericExample {
        public static void main(String[] args) {
            // Non-generic ArrayList (before Generics in Java 5) - No type safety at compile time
            ArrayList list = new ArrayList();
            list.add("Hello");
            list.add(10); // No compile-time error, but could cause issues later

            String str = (String) list.get(0); // Need to cast, potential ClassCastException at runtime
            // Integer num = (Integer) list.get(0); // ClassCastException at runtime!

            // Generic ArrayList (using Generics) - Compile-time type safety
            List<String> stringList = new ArrayList<>(); // Type parameter <String> specified
            stringList.add("Hello");
            // stringList.add(10); // Compile-time error: Incompatible types - type safety enforced

            String str2 = stringList.get(0); // No need to cast, type is known at compile time
        }
    }
    ```

38. **Explain the concept of garbage collection in Java. How does Java garbage collection work? (Briefly)**
    *   **Answer:** Garbage collection (GC) in Java is an automatic memory management process that reclaims memory occupied by objects that are no longer in use by the application. Java, unlike languages like C and C++, automates memory management, relieving developers from manual memory allocation and deallocation (using `malloc`/`free` or `new`/`delete`).
    *   **How Java Garbage Collection Works (Simplified):**
        1.  **Memory Allocation (Heap):** When you create objects in Java using `new`, memory is allocated from the heap.
        2.  **Object Reachability Tracking:** The JVM's garbage collector continuously tracks which objects are "reachable" or "live." An object is considered reachable if it is still being referenced directly or indirectly by the application's running code (through references from root objects like static variables, local variables on the stack, or native code).
        3.  **Marking Phase:** The garbage collector starts from a set of root objects and traverses the object graph, marking all objects that are reachable. Unreachable objects are not marked.
        4.  **Sweeping (or Deletion) Phase:** After marking, the garbage collector identifies unmarked objects (garbage - objects no longer reachable). It then reclaims the memory occupied by these garbage objects, making the memory available for new object allocations.
        5.  **Compaction (Optional):** Some garbage collection algorithms also include a compaction phase. Compaction rearranges live objects in memory to reduce fragmentation and make allocation of new objects more efficient.
        6.  **Garbage Collection Cycles:** Garbage collection is an ongoing process that runs periodically in the background. The frequency and timing of GC cycles depend on the specific GC algorithm used by the JVM and memory pressure (how much memory is being used).
    *   **Garbage Collection Algorithms (Briefly):** Java JVMs use various garbage collection algorithms, including:
        *   **Mark and Sweep:** Simple algorithm, marks reachable objects, then sweeps (deletes) unmarked objects. Can lead to fragmentation.
        *   **Mark and Compact:** Mark and sweep, but also compacts memory by moving live objects together to reduce fragmentation.
        *   **Copying Collectors:** Divide heap into regions, copy live objects from one region to another, leaving garbage behind. Efficient but can have overhead.
        *   **Generational Garbage Collection:** Most modern JVMs use generational GC. Divides heap into generations (Young Generation, Old Generation, Permanent Generation/Metaspace). Objects are initially allocated in the Young Generation. Young Generation GC is frequent and fast. Objects that survive multiple Young Generation GC cycles are promoted to the Old Generation. Old Generation GC is less frequent and more expensive. Different GC algorithms might be used for different generations. Examples: Serial GC, Parallel GC, CMS (Concurrent Mark Sweep) GC, G1 (Garbage-First) GC.

39. **What is the Java Virtual Machine (JVM)? What is its role in Java's platform independence?**
    *   **Answer:** The Java Virtual Machine (JVM) is a runtime environment that executes Java bytecode. It is a crucial component of the Java platform and is responsible for Java's "write once, run anywhere" (WORA) platform independence.
    *   **Role of JVM in Java's Platform Independence:**
        1.  **Compilation to Bytecode:** Java source code (`.java` files) is compiled by the Java compiler (`javac`) into platform-independent bytecode (`.class` files). Bytecode is not machine code specific to any particular operating system or hardware architecture.
        2.  **JVM as an Abstraction Layer:** The JVM acts as an abstraction layer between the Java bytecode and the underlying operating system and hardware.
        3.  **Platform-Specific JVM Implementations:** JVMs are implemented specifically for each operating system and hardware platform (e.g., Windows JVM, Linux JVM, macOS JVM). Each JVM implementation understands how to execute Java bytecode on its specific platform.
        4.  **Bytecode Interpretation and Just-In-Time (JIT) Compilation:** When you run a Java program, the JVM loads the bytecode and executes it. JVMs typically use a combination of bytecode interpretation and Just-In-Time (JIT) compilation.
            *   **Interpreter:** Initially, bytecode may be interpreted (executed line by line by the JVM interpreter).
            *   **JIT Compiler:** For performance optimization, the JVM's JIT compiler dynamically compiles frequently executed parts of the bytecode into native machine code during runtime. This compiled machine code is then executed directly by the processor, improving performance.
        5.  **Platform Independence Achieved:** Because Java bytecode is executed by the JVM, and JVM is implemented for different platforms, the same Java bytecode can run on any platform that has a compatible JVM, without recompilation. This is how Java achieves platform independence.

41. **Explain the difference between `String`, `StringBuilder`, and `StringBuffer` in Java. When would you use each?**
    *   **Answer:** `String`, `StringBuilder`, and `StringBuffer` are classes in Java used to represent and manipulate sequences of characters (strings). They differ in mutability and thread-safety, which affects their performance and use cases.
        *   **`String`:**
            *   **Immutable:** `String` objects are immutable. Once a `String` object is created, its value cannot be changed. Any operation that appears to modify a `String` actually creates a new `String` object.
            *   **Thread-Safe:** Immutable `String`s are inherently thread-safe because their state cannot be modified after creation.
            *   **Performance:** Immutability can lead to performance overhead when performing frequent string modifications, as new `String` objects are created repeatedly. String concatenation using `+` operator can be inefficient for large strings due to repeated object creation.
            *   **Use Cases:** Use `String` when you need immutable strings, for string literals, storing constant strings, and in scenarios where string modifications are infrequent.
        *   **`StringBuilder`:**
            *   **Mutable:** `StringBuilder` objects are mutable. You can modify the contents of a `StringBuilder` object directly without creating new objects.
            *   **Not Thread-Safe:** `StringBuilder` is not thread-safe. It is designed for single-threaded environments.
            *   **Performance:** More efficient than `String` for frequent string modifications (appending, inserting, deleting characters) as it avoids creating new objects for each modification.
            *   **Use Cases:** Use `StringBuilder` when you need to perform frequent string modifications in a single-threaded environment, such as building strings in loops, string concatenation, or text processing within a single thread.
        *   **`StringBuffer`:**
            *   **Mutable:** `StringBuffer` objects are also mutable, similar to `StringBuilder`.
            *   **Thread-Safe:** `StringBuffer` is thread-safe. Its methods are synchronized, making it safe to use in multi-threaded environments where multiple threads might modify the string concurrently.
            *   **Performance:** Thread-safety comes with a performance overhead due to synchronization. `StringBuffer` is generally slightly slower than `StringBuilder` in single-threaded environments.
            *   **Use Cases:** Use `StringBuffer` when you need to perform frequent string modifications in a multi-threaded environment where thread-safety is required to prevent data corruption due to concurrent access.

    | Feature         | `String`                  | `StringBuilder`              | `StringBuffer`               |
    |-----------------|---------------------------|-------------------------------|------------------------------|
    | Mutability      | Immutable                 | Mutable                       | Mutable                      |
    | Thread-Safety   | Thread-Safe               | Not Thread-Safe               | Thread-Safe                  |
    | Performance     | Less efficient for modifications | More efficient for modifications | Slightly slower than `StringBuilder` |
    | Synchronization | Implicitly thread-safe    | No synchronization            | Synchronized methods         |
    | Use Cases       | Immutable strings, constants | Frequent modifications (single-threaded) | Frequent modifications (multi-threaded) |

42. **What are lambda expressions in Java? What are their benefits?**
    *   **Answer:** Lambda expressions (introduced in Java 8) are a concise way to represent anonymous functions (functions without a name). They provide a way to treat code as data, making it easier to pass behavior as arguments to methods, particularly for functional programming paradigms and event handling.
    *   **Syntax of Lambda Expression:** `(parameters) -> { body }`  or `parameter -> expression` (for single parameter and single expression body).
    *   **Benefits of Lambda Expressions:**
        *   **Concise Code:** Lambda expressions significantly reduce boilerplate code, especially for anonymous inner classes used for functional interfaces (interfaces with a single abstract method). They make code shorter and easier to read.
        *   **Functional Programming Enablement:** Lambda expressions facilitate functional programming style in Java. They allow you to treat functions as first-class citizens, pass them as arguments, and return them from methods.
        *   **Improved Readability and Maintainability:** Code using lambdas can be more readable and easier to understand, especially for functional operations like filtering, mapping, and iteration on collections.
        *   **Parallel Processing and Concurrency:** Lambda expressions are often used with Java Streams API to enable parallel processing of collections and data, improving performance for large datasets.
        *   **Method References:** Lambda expressions can be simplified further using method references (e.g., `ClassName::methodName`), making code even more concise.
        *   **Example (using Lambda with Collections):**

        ```java
        import java.util.ArrayList;
        import java.util.List;

        public class LambdaExample {
            public static void main(String[] args) {
                List<Integer> numbers = new ArrayList<>();
                numbers.add(1);
                numbers.add(2);
                numbers.add(3);
                numbers.add(4);

                // Using anonymous inner class (before Lambdas) to iterate and print even numbers
                numbers.forEach(new java.util.function.Consumer<Integer>() {
                    @Override
                    public void accept(Integer n) {
                        if (n % 2 == 0) {
                            System.out.println(n);
                        }
                    }
                });

                // Using Lambda expression (concise and readable) - equivalent to above
                numbers.forEach(n -> {
                    if (n % 2 == 0) {
                        System.out.println(n);
                    }
                });

                // Even more concise Lambda for a single expression body
                numbers.forEach(n -> {if (n % 2 == 0) System.out.println(n);});

                // Even more concise Lambda, single parameter, single expression body
                numbers.forEach(n -> System.out.println(n)); // Prints all numbers

                // Using method reference (even more concise if method already exists)
                numbers.forEach(System.out::println); // Method reference to System.out.println()
            }
        }
        ```

43. **What is the difference between `==` and `equals()` method in Java when comparing objects?**
    *   **Answer:** `==` operator and `equals()` method are used for comparison in Java, but they compare objects differently.
        *   **`==` Operator (Reference Equality):**
            *   Compares object references (memory addresses).
            *   Checks if two reference variables point to the *same* object in memory.
            *   For primitive types (e.g., `int`, `char`, `boolean`), `==` compares the actual values.
            *   For object references, `==` returns `true` if and only if both references point to the exact same object instance in memory.
        *   **`equals()` Method (Object Equality):**
            *   Compares the *content* or *value* of objects.
            *   Defined in the `Object` class (the root of all Java classes). By default, the `equals()` method in `Object` class behaves the same as `==` (compares references).
            *   **Should be overridden in classes to define meaningful object equality based on the object's state (content).** For example, in `String` class, `equals()` is overridden to compare the character sequences of two strings, not their memory addresses.
            *   When you override `equals()`, you should also typically override `hashCode()` to maintain consistency (if two objects are equal according to `equals()`, their `hashCode()` values should be the same).
        *   **When to Use Which:**
            *   Use `==` when you want to check if two references point to the *same* object instance (reference equality). This is less common for comparing object content.
            *   Use `equals()` when you want to check if two objects are considered "equal" based on their *content* or *value* (object equality). This is the typical way to compare objects for logical equality (e.g., are two `String` objects containing the same sequence of characters? are two `Person` objects representing the same person based on name and ID?).

    ```java
    public class Main {
        public static void main(String[] args) {
            String str1 = new String("hello");
            String str2 = new String("hello");
            String str3 = str1;

            System.out.println(str1 == str2);       // Output: false (different object instances in memory)
            System.out.println(str1.equals(str2));  // Output: true (content is the same - String's equals() is overridden)

            System.out.println(str1 == str3);       // Output: true (both references point to the same object)

            Integer num1 = new Integer(10);
            Integer num2 = new Integer(10);
            int num3 = 10;

            System.out.println(num1 == num2);      // Output: false (different Integer objects)
            System.out.println(num1.equals(num2)); // Output: true (content is the same - Integer's equals() is overridden)
            System.out.println(num1 == num3);      // Compile error: Incompatible types, cannot compare object reference with primitive using ==
            System.out.println(num1.intValue() == num3); // Output: true (comparing primitive values after unboxing)
        }
    }
    ```
